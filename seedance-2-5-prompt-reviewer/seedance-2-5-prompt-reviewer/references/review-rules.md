# Seedance 2.5 审查规则

本页是《Seedance 2.5 提示词指南》的任务型提炼，供审查或改写提示词时完整读取。

## 1. 基础结构与素材

基础公式：`主体 + 动作或事件 + 场景与环境（可选）+ 视觉风格（可选）+ 运镜或切镜（可选）+ 声音（可选）`。

素材范围与稳定性建议：

| 类型 | 上限 | 推荐范围 |
|---|---:|---|
| 图片 | 30 张，单张不超过 4K | 主体图 1–8 个主体 |
| 视频 | 10 段，总时长不超过 30 秒 | 1–5 个主体，单段 5–10 秒 |
| 音频 | 10 段，总时长不超过 30 秒 | 只保留任务直接相关声音 |
| 视频编辑参考图 | 与视频共同使用 | 1–5 张 |

总参考素材最多 50 份。超过推荐范围可尝试，但稳定性通常下降。多视角主体优先拆成多张独立图，不把大量视角塞进单张拼图。

每份素材都写职责，例如：

```text
@图片1用于<人物A>的五官、发型和服装，不采用图片背景。
@视频1用于<人物A>的动作节奏和运镜，不采用视频中的人物身份与场景。
@音频1用于<人物A>的音色和指定台词。
```

多主体不能写“图片1至4分别定义四人”，必须逐一映射。不同视角共同定义同一物体时，明确“共同定义同一对象，成片始终只有一个”。

参考视频已准确给出动作、运镜和顺序时，只说明继承哪些内容，避免重复描述造成冲突。白模视频仍需写最终主体、场景、动作和风格。

## 2. 声音与文字

特殊字符：音乐 `()`、音效 `<>`、台词 `{}`、字幕 `【】`。

非中文台词明确：语言 + 地区变体/口音 + 表达方式 + 说话人 + `{台词}`。需要排除声音时明确类别，如“无背景音乐，只保留对白、环境声和动作音效”。

必须完全准确的字幕、公式、标牌和产品参数应通过前期合成或后期制作完成，不承诺模型生成绝对准确。

## 3. 多素材与长视频

多素材推荐顺序：逐份职责 → 主体映射 → 按人物/道具/场景/动作声音分组 → 重要主体设定 → 分场景调用。

检查：

- 人物外貌、服装、动作、站位和台词是否会互换；
- 道具是否有唯一持有者、数量和位置；
- 场景素材是否误带人物或前景物；
- 当前场景是否只调用需要的素材。

长视频用阶段组织。每阶段写“开始/承接状态 → 一个主要事件 → 可观察结束状态”。必要时用时间戳控制关键交接或转场；时间段必须连续、不重叠。时间戳只是节奏预算，不是帧级剪辑点，也不能要求一秒内完成多个复杂动作。

## 4. 锁定参数

| 任务 | 画幅 | 时长 |
|---|---|---|
| 视频编辑 | 自动保持输入视频比例，不支持另设 | 自动基本保持输入时长，不支持另设；可有约 0.3 秒差异 |
| 首帧/首尾帧生视频 | 由首帧比例锁定；首尾图应同画幅 | 支持设置 |
| 视频延长 | 自动保持输入视频比例，不支持另设 | 支持设置延长时长 |

生成页面或 API 可调的参数与提示词正文分开。不得在正文中写与锁定规则冲突的比例或时长。

## 5. 视频编辑

必须包含：

1. `@视频1` 是唯一编辑母版；
2. 明确修改对象、作用区域/时间段、目标数量；
3. 目标图片/音频只负责指定属性；
4. 列明保持的人物、场景、动作、构图、镜头、遮挡、声音和事件顺序；
5. 替换对象继承原对象出现、运动、遮挡和离开的时点、路径与速度。

主体替换只改主体；背景替换只改主体轮廓外区域；声音编辑区分对白、语言、音色、音乐、环境声和音效。不能把生成式编辑说成逐帧不变。

## 6. 视频延长

向后延长：新片段第一画面承接原视频尾帧，再写后续事件。

向前延长：先写前置事件，最后画面明确达到原视频首帧状态。

两者都检查人物、服装、道具、背景、摄影轴线、机位构图、光线、声音和运动趋势连续；同一主体不重复、不分裂。其他参考素材不能取代原视频边界画面的控制。向前延长还需声明只在原视频开始后出现的素材不得提前出现。

## 7. 首尾帧、关键帧、宫格和白模

首尾帧：分别声明 `@图片1作为首帧`、`@图片2作为尾帧`，不能合并一句；两图画幅一致。其他图片只定义指定属性，不改变首尾构图。

多关键帧：首句声明图片顺序，再逐图说明关键状态；它控制阶段顺序与状态，不等于逐帧复刻。

宫格故事板：写读取顺序和每格的动作、景别/运镜；通常控制在 15 格以内；不继承线稿风格、文字标注或占位人物，除非明确需要。
⚠️ **宫格占位人物污染（2026-08-28 Scene2 GU-01 实测）**：宫格内的示意/占位人物会被 2.5 读成真人形象（B 镜出现与主角无关的戴眼镜男）。文字声明「不采用人物」挡不住图面信号。
- 处理：PIL 对含人物的格 `GaussianBlur(radius=10)` 强模糊 → 重传；只保留构图几何。
- 先确认宫格布局（横排/竖排）：`ImageStat` 对比各 1/3 区 stddev（远景格最高、空镜格最低），写对读取顺序。
- 提示词同时写死「不从 @图片N 任何一格采用人物的脸型/体型/发型/服装/肤色/眼镜等外形特征」。

粗粒度白模：只继承动作路径、站位、机位、运镜、切镜、光影、声音节奏与空间关系；逐一映射几何体。

细粒度白模：保持完整结构、动作、空间和镜头，重渲染人物、材质、颜色、场景或风格；素材应尽量去除轨迹线、坐标轴、控制器和相机锥体。

## 8. 一键成片与无缝转场

一键成片必须说明：素材职责、图片顺序或允许自由编排、每张图的动态幅度、剪辑/转场/包装风格、声音。多人物或多商品仍需逐一绑定。

无缝转场必须说明：前段视频职责、后段视频职责、触发动作、镜头方向与速度、画面形状/材质/光线/空间如何变化、最终到达的构图、声音衔接。生成式过渡不是逐像素剪辑拼接。

## 9. 情绪与摄影

情绪用 2–4 个可观察表现表达，如视线、眉头、嘴角、呼吸、肩膀和手部动作。多次转折按触发事件分阶段。

常用景别、推拉摇移跟、环绕、俯冲、手持、第一人称等可直接写。小众或含义不一的术语必须补充：作用主体 + 可见变化 + 前/背景关系 + 方向/速度。一个镜头优先一种主运镜。

## 10. 最终判定清单

- 主体与主要事件是否明确；
- 每份素材是否写采用/必要时不采用的内容；
- 人物、商品、道具是否逐一绑定；
- 多素材是否按场景调用；
- 每阶段是否只有一个主要变化并有结束状态；
- 人数、服装、道具归属与空间方向是否稳定；
- 编辑是否有唯一母版、范围、目标数量和保持内容；
- 抽象情绪与摄影术语是否可观察；
- 首尾帧与关键帧是否逐张说明，首尾画幅是否一致；
- 白模类型和继承范围是否正确；
- 锁定参数是否遵守；
- 延长边界的画面、运动、声音是否连续；
- 一键成片和转场的必要结构是否完整。

## 12. 甲方交付文档转写（韩世浩 Part2 模式，2026-08-28 用户确立）

甲方给的交付文档（如 `P26001-DRAMA-..._最完整交付文件_v5.docx`）里的「可貼上提示詞」、故事板、分镜描述**全部视为参考**，不是可直接提交的提示词。必须按本 skill 规范重写。

### 从甲方文档提取什么

| 甲方内容 | 处理 |
|---|---|
| 镜头 A/B/C、机位、景别、运镜描述 | 提取，转成可执行的中文分镜段落 |
| 对白（如「它是安靜、永恆不變的純粹本質，」）| 转简体 + `{}` 台词标注，逐字保留 |
| 时间码（0.0–7.6 / 7.6–12.0）| **按甲方原时间码写进提示词**；不硬凑通道档位（如 30s 档）——若通道限制时长，镜头节奏预算按比例缩放并在提示词注明"剪辑以母带时间码为准" |
| 素材分工（@Image 1 只定義帆船…）| 扩成逐份「采用什么/不采用什么」职责声明 |
| 声音原则（无 BGM / 旁白后期 / 对白逐字）| 写进提示词（无 BGM、不生成旁白声音）|
| 调色 / 前后篇衔接要求 | 写进提示词（如"冷青绿海面、与 Part1 结尾调色一致"）。⚠️ **Part2 经验（2026-08-28）**：Part1 结尾天光已是亮的，衔接段**禁止"亮暗亮"**——开场不要写"略阴/渐亮"，全段亮度恒定 |
| 故事板宫格图 | 只锁机位；**占位人物必须 PIL blur 掉**（r≥5）或提示词声明"不从任何一格采用人物外形"；读取顺序按实际布局（横排左中右 / 竖排上中下）。⚠️ **仅限 Part2（韩世浩·水與波浪章）**：甲方明确该章故事板图不作参考 → 不挂宫格图，机位全部纯文字描述（景别/角度/位置/运镜写全）。其他项目/章节宫格仍可用，但必须处理占位人物 |
| 参考视频 | 只借神态/呼吸/眼神/转头，排除手部与配饰 |
| 参考音频 | ≤30s；mp3；只供音色节奏；不用旁白内容 |

### 甲方半成品常见的坑（都要在重写时修）

- 无 `{}` 台词标注（甲方用「」）→ 改 `{}`
- 繁体/全角 → 简体 + 规范标点
- 「無人物近鏡」歧义（被读成"没人"）→ 明确"甲板上可辨识 Johnny 远景，无近景特写"
- 时间码与通道档位冲突 → 按甲方时间码，不凑档
- 无素材职责边界 → 逐份补"采用/不采用"
- 宫格占位人物 → blur 或声明排除
- 未声明服装/外形唯一权威 → 补"@图片N 是外形唯一权威，其余图不参与"

### 产出物

正式提示词 = 参考素材职责段 + 保持一致段 + 主提示词（镜头分段/硬切/时间码/对白）+ 提交前自检清单。与甲方原文的差异点写进「优化点对照」，供用户复核。
