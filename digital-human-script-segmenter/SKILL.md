# 数字人脚本切分

把口播时长当作可校准的数据问题，把切分当作语义问题。不要用通用平均语速替代人物样本，也不要为了填满 15 秒破坏原意。

先确认交付模式：用户只要求切稿时止于第三步；只有用户要求视频提示词或准备生成视频时，才执行第四、第五步。用户只要求人物、场景、表情、道具或色板等视觉资产生图提示词时，转交 `ai-video-asset-director`，本 Skill 不重写资产提示词规则。

## 首先定位工具和资料

将本 Skill 内的 `scripts/speech_timing.py` 解析为绝对路径，后续命令中的 `$TIMING_TOOL` 指向它。

需要生成 Seedance 提示词时，读取 [references/seedance-prompt-rules.md](references/seedance-prompt-rules.md)。只有需要查看完整官方细节、且当前工作区存在原始指南时，才额外读取：

`【04.原始资料】/技术教程/seedance/Doubao Seedance 2.0 系列提示词指南.md`

原始指南不存在时使用 Skill 内置参考，不得因此阻塞任务。

## 第一步：取得或建立人物语速档案

优先使用用户提供的现成人物档案。没有档案时，请用户提供：

- 人物名称；
- 一段确认听感自然的逐字稿；
- 该段实际口播时长（秒）；
- 文中数字、缩写、专名的实际读法。

中文和英文分别标定。中文速度是有效汉字数/秒；英文速度是按读音映射和自动规则得到的音节数/秒。自动音节统计用于初算；数字、缩写、专名和读音不确定的单词必须由用户确认实际读法。样本总时长包含人物自然停顿，因此无需另造停顿系数。

先分析样本：

```bash
python3 "$TIMING_TOOL" analyze \
  --text "<样本文稿>" \
  --reading-map '<JSON 对象；无则省略>'
```

确认所有 `ambiguous_tokens` 的实际读法后建立档案：

```bash
python3 "$TIMING_TOOL" calibrate \
  --speaker "<人物名>" \
  --text "<样本文稿>" \
  --duration <实际秒数> \
  --language <zh|en|mixed> \
  --reading-map '<JSON 对象；无则省略>' \
  --body-language '<少量|适中|较多>' \
  --pose-lock '<需要保持的参考姿态>' \
  --output "<人物名>-speech-profile.json"
```

纯中文或纯英文样本使用总时长即可。中文样本中的缩写若按英文字母发音，也属于混合发音，不能把整段时长只分给中文。混合语言不能仅凭总时长分离出两种速度；若要用同一段混合样本同时标定，必须另外提供中文部分和英文部分的实际时长，并在命令中加入 `--zh-duration` 与 `--en-duration`。更稳妥的做法是分别提供一段纯中文和纯英文样本。任务文本包含档案未覆盖的语言时，要求补充对应语言样本，不得套用默认速度。

档案字段及人工保存模板见 [references/speaker-profile.md](references/speaker-profile.md)。

## 第二步：分析全文并设计切口

先用档案分析全文：

```bash
python3 "$TIMING_TOOL" estimate \
  --profile "<人物档案.json>" \
  --text "<完整文案>" \
  --reading-map '<JSON 对象；无则省略>'
```

如果出现 `ambiguous_tokens`，先依据上下文提出最可能读法并清楚标注假设；读法会显著改变时长或确实无法判断时，再询问用户。然后按以下顺序切分：

1. 优先在句号、问号、感叹号后的完整语义处切。
2. 其次在分号、冒号、完整从句或自然换气处切。
3. 15 秒是硬上限，9 秒是成本风险线。结合人物档案容差确定安全上限：`安全目标上限 = 15 ÷ (1 + 容差)`；默认 8% 容差时约为 13.9 秒。
4. 优先规划在 12 秒至安全目标上限之间；预计时长虽未超过 15 秒、但保守上限超过 15 秒时标为临界，不作为首选切法。
5. 短于 9 秒时，优先与前后语义相连的片段合并；不得合并成保守上限超过 15 秒的片段。
6. 不拆开固定搭配、数字与单位、姓名、专名、引语、条件句、因果关系、转折关系或“前半句铺垫 + 后半句结论”的逻辑单元。
7. 如果一句话超过安全目标上限，优先寻找内部完整语义边界；如果切开会导致上下文割裂，保留原文并给出可选改写建议，而不是直接硬切。
8. 默认不改字，只移动切口和补充必要标点。无法兼顾语义与时长时保留原文，另列“可选改写建议”。

将每个候选片段分别交给 `estimate` 复核，同时查看 `estimated_seconds`、`conservative_seconds` 与 `status`。预计时长保留一位小数。纯标点、空白和格式字符不计入速度单位。

## 第三步：输出切分结果

先给出：

### 人物语速摘要

- 人物与档案来源
- 中文字/秒、英文音节/秒（仅列已有基准）
- 标定样本时长与容差
- 数字、缩写和专名读法假设
- 全文预计总时长、片段数，以及按用户价格信息估算的成本提示；没有明确单价时只说明片段数量和短片段成本风险，不虚构金额

再使用以下表格：

| 段落 | 逐字口播 | 计速单位 | 预计 / 保守时长 | 状态 | 切分理由 |
|---|---|---:|---:|---|---|
| 1 | … | 中文 32 字 / 英文 0 音节 | 13.4 / 14.5 秒 | 理想 | 完整句收束 |

状态只能是：

- `理想`：预计 12 秒以上，且保守上限不超过 15 秒；
- `可接受`：9.0–11.9 秒，且保守上限不超过 15 秒；
- `临界`：预计不超过 15 秒，但保守上限超过 15 秒；
- `偏短`：少于 9.0 秒；
- `超限`：预计超过 15.0 秒。

必须检查所有片段拼接后与原文文字一致；允许的差异只有切口、空白和标点。不得静默删字、换词或重写。使用脚本进行硬验证：

```bash
python3 "$TIMING_TOOL" validate-integrity \
  --original "<完整原文>" \
  --segment "<片段 1>" \
  --segment "<片段 2>"
```

## 第四步：确认肢体语言偏好

生成提示词前，先读取已有客户偏好。没有记录时必须确认客户希望肢体语言 `少量`、`适中` 还是 `较多`，并将结果记入人物或项目档案。不要每个片段重复询问。

- `少量`：每个 10–15 秒片段通常只安排 1 次轻微手势，其余时间维持参考姿态；严肃内容可以完全不做手势，只使用目光、呼吸和轻微表情变化。
- `适中`：每个 10–15 秒片段安排 1–2 次自然手势，动作之间有明确的保持与回位阶段。
- `较多`：每个 10–15 秒片段可安排 2–3 次动作，但仍以低缓、连续的小动作为主，不频繁换姿势。

人物、客户或章节的具体要求必须保存在人物或项目档案中，不要写死在通用 Skill。项目覆盖配置优先于人物默认值，人物默认值优先于通用规则。

如果甲方或项目明确要求“主机位 + 特写机位”分别出片，先按镜头分层再写提示词：主机位负责完整叙述，特写机位负责情绪、转折、价值收束或重点句。合并生成时，中间必须预留可切分的气口，不能把两段直接连成无停顿直读；切分点附近优先写成短暂停顿、视线下沉、浅慢吸气或保持姿势。

## 第五步：为每段生成 Seedance 提示词

逐段输出一个可直接复制的代码块。口播台词必须逐字保留并放在官方规定的 `{}` 内。

用户用“不要太开心”“不要调侃”“不要太沉重”等表达需求边界时，不要把这些否定句原样写进正式提示词。先把边界翻译成正向表演目标，例如“沉稳、自然、真诚、平实清晰、有交流感、有信念感、克制而坚定”。表演控制尽量使用正向描述；字幕、Logo、水印等输出排除项可以使用经过验证的明确约束句式。

先确定该片段的实际生成时长：已有音频或平台设置时使用其实际时长；否则将保守时长向上取整为整数秒，最高 15 秒。随后编写连续动作时间轴：

1. 从 `00` 秒开始，到实际生成时长结束。
2. 使用少量、连续的粗粒度时间段覆盖全片；“覆盖每一秒”不等于“每一秒安排一个新动作”。
3. 时间段不能有缺口、重叠或超过片段时长。
4. 没有动作的时段也要明确写“保持参考坐姿”或“保持当前手势”。
5. 时间轴控制动作时机，不按每句话机械更换动作。
6. 10–15 秒口播通常使用 3–5 个阶段；客服建议精确写清每段“保持什么姿势”，同时控制动作数量，避免复杂时间轴增加随机性。

默认提示词结构：

```text
主体与场景：<明确绑定参考人物和稳定场景>。
表演：<与内容一致的情绪外化、表情、视线、呼吸和低缓连续小动作>。
镜头：<景别>，<一种主要运镜>，动作自然连贯，口型与台词同步。
时间轴：<从 00 秒连续覆盖到片段结束，每段说明动作或保持姿态>。
人物使用<语言>说道{<该段逐字口播>}
画面：高清，细节自然，光影稳定，符合内容氛围。
声音与画面：视频仅包含人物口播人声，环境安静无杂音；画面仅有人物及原有背景，不叠加任何文字内容；人物身份、服装、坐姿、场景、光线和音色保持一致。
```

当参考图不是正面机位时，必须额外锁定空间关系：人物朝向、椅子朝向、机位角度和背景透视必须与参考图片一致。如果参考图是侧面或半侧面机位，人物和座椅也保持同一侧向关系，不把人物转成正面机位。不要只写“保持坐姿”，否则模型可能在背景透视不变的情况下改变人物朝向，造成空间割裂。

情绪必须具象化，不只写“悲伤”“开心”等抽象标签。沉重内容可使用轻微低头、短暂停顿、眉间轻微收紧、目光下沉等克制表现，不自动升级为哭泣、崩溃或戏剧化动作。一个镜头只指定一种主要运镜，数字人口播默认优先固定机位。

### 表演与动作细化

- 目光默认写成“交流式视线自然看向镜头附近”，允许自然眨眼、极轻微视线偏移和短暂思考停顿；避免把人物写成持续“直视镜头”或“稳定目光”，这容易生成死盯提词器的效果。
- 停顿不要只靠台词里的破折号或括号。台词可保留 `——`，但时间轴里要写清“说完某个词后短暂停顿约半秒，视线下沉，做一次很浅、很慢的自然吸气，再接后半句”。
- 如果该段是合并生成、后期需要裁切，提示词里必须明确留气口；不要把可裁切的两段写成一口气直读到底。
- 沉重内容的呼吸用“很浅、很慢的自然吸气”或“几乎不可察觉的缓慢呼吸”，不要写成大幅度深呼吸，以免生成戏剧化抬胸或耸肩。
- 自我经历、身份背景、个人信念等“说自己”的内容，适合用克制的自我指涉动作：右手从膝上轻微抬起到胸前下方，动作幅度小，不遮挡脸部；比泛泛写“说明性小动作”更贴合语义。
- 数据、事实、历史创伤内容适合锁手：双手自然交叠放在膝上，手掌保持合拢状态，只允许手指极轻微收紧。
- 景别参考、人物参考、表情参考和音频参考必须分清素材角色。若某素材只是景别参考，提示词要写“画面景别和构图参考”，不要让模型把它当人物脸或表情参考。素材 asset id 不确定时先向用户确认，不要猜。
- 如果视频提示词依赖新生成的视觉资产，先确认资产角色标注是否完整：人物身份、妆造、表情、场景、道具、色板、景别各自用途必须清楚；缺关键资产时标记为“需 ai-video-asset-director 先补资产提示词”，不要在本 Skill 里临时重写资产生成规则。
- 如果用户要求“肢体语言少”，每段动作应和语义匹配：自我指涉、数据强调、沉重停顿、价值收束等场景各用不同微动作，不要机械地每段都抬手。

生成后验证时间轴：

```bash
python3 "$TIMING_TOOL" validate-timeline \
  --text "<完整提示词>" \
  --duration <实际生成秒数>
```

验证不通过时必须修正提示词，不能把有时间缺口的版本交付给用户。

## 质量检查

交付前逐项确认：

- 使用的是该人物档案，不是通用语速。
- 中文按有效汉字、英文按实际发音音节计数。
- 数字、缩写、中英混排已有读音映射或明确假设。
- 每段都经过脚本复核，预计时长和保守时长均为一位小数。
- 优先 12 秒至安全目标上限；偏短、临界和超限片段均显式标记。
- 拼接后的逐字内容没有遗漏或改写。
- 每段提示词含逐字台词、具象情绪、小动作、单一运镜和默认约束。
- 用户需求边界已转成正向表演目标；正式提示词中没有无意保留的“不要/不/避免/不过分”等否定式表演描述。
- 目光是交流式视线，不是死盯镜头；必要时包含自然眨眼、轻微视线偏移和短暂停顿。
- 景别、表情、人物、音频等参考素材角色清楚，没有把景别素材写成表情素材。
- 没有把 image2.0、GPT Image 2 或 nanobanana 参数混进 Seedance 视频提示词正文；视觉资产生图提示词已转交或引用 `ai-video-asset-director`。
- 人物朝向、椅子朝向、机位角度和背景透视关系已锁定，尤其是侧面或半侧面书房机位。
- 动作与语义匹配，例如自我经历用自我指涉动作，沉重转折用停顿和浅慢呼吸，数据事实用手指轻收或锁手。
- 已确认并遵循客户的肢体语言密度偏好。
- 动作时间轴从 00 秒连续覆盖到实际片段结束，没有缺秒、重叠或越界。
- 台词使用 `{}`，不使用普通引号替代官方台词符号。
